## 1. Reactor + ThreadLocal 스레드 불일치 🔴

**대상 파일**
- `src/main/java/com/krdevops/springai/chat/controller/EgovOllamaChatController.java:30, 40`
- `src/main/java/com/krdevops/springai/chat/service/impl/EgovSessionAwareChatServiceImpl.java:70`

**현재 코드**
```java
// EgovOllamaChatController.java:30
setupSession(sessionId, message);  // Servlet 스레드에서 ThreadLocal 설정

// EgovOllamaChatController.java:40
.doFinally(signal -> SessionContext.clear());  // Reactor 스레드에서 실행
```

**문제 시나리오**
- `setupSession()`은 **Servlet 스레드(tomcat-http-nio-xxx)** 에서 ThreadLocal 설정
- `doFinally` 및 `getCurrentSessionId()`는 **Reactor 스레드(boundedElastic)** 에서 실행
- 서로 다른 스레드이므로 ThreadLocal 값 공유 불가
- 결과: **모든 스트리밍 요청이 "default" 세션으로 처리** → 세션별 대화 이력 관리 동작 안 함

**수정 방향**
- 세션 ID를 메서드 파라미터로 직접 전달하는 구조로 변경
- 또는 Reactor Context 전파 방식(`contextWrite`) 적용

**영향 범위**
`SessionContext.java`, `EgovOllamaChatController.java`, `EgovSessionAwareChatServiceImpl.java`

## 2. ThreadLocal 누수 (예외 경로) 🔴

**대상 파일**
- `src/main/java/com/krdevops/springai/chat/context/SessionContext.java:9`
- `src/main/java/com/krdevops/springai/chat/controller/EgovOllamaChatController.java:68-81`

**현재 코드**
```java
// SessionContext.java:9
private static final ThreadLocal<String> CURRENT_SESSION_ID = new ThreadLocal<>();
```

**문제 시나리오**
- `setupSession()` 내부에서 `sessionExists()` 또는 `generateSessionTitle()` 예외 발생 시
- Flux 파이프라인 구성 전에 예외 전파 → `doFinally` 미실행
- Tomcat 스레드 풀 재사용으로 **이전 요청의 세션 ID가 잔존**
- 결과: 다른 사용자의 요청이 잘못된 세션 컨텍스트로 처리 (세션 혼선)

**수정 방향**
```java
// try-finally 패턴 적용
try {
    setupSession(sessionId, message);
    return streamResponse(...);
} finally {
    SessionContext.clear();
}
```

**영향 범위**
`EgovOllamaChatController.java` 단일 파일

## 3. CSRF 비활성화 + permitAll 남용 🔴

**대상 파일**
- `src/main/java/com/krdevops/springai/config/SecurityConfig.java:44, 51`

**현재 코드**
```java
// SecurityConfig.java:44
.csrf(csrf -> csrf.disable())

// SecurityConfig.java:47-51
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/sse", "/mcp/**", "/", "/ai/**",
        "/api/chat/**", "/api/ollama/**", "/api/documents/**").permitAll()
    .requestMatchers("/api/**").authenticated()
    .anyRequest().permitAll()   // ← 모든 미매칭 경로 허용
)
```

**문제 시나리오**
- `/api/chat/**` — 인증 없이 LLM 호출 비용 발생 엔드포인트 노출
- `anyRequest().permitAll()` — 새 컨트롤러/엔드포인트 추가 시 자동 노출 (보안 기본 거부 원칙 위반)
- CSRF 전면 비활성화 — 브라우저 기반 Chat UI(`/ai/**`)에서 CSRF 공격 가능
- **eGovFrame 보안 규칙 위반**: `egov-security.md` — "CSRF 토큰 비활성화 금지", "permitAll() 남용 금지"

**수정 방향**
```java
// anyRequest 변경
.anyRequest().denyAll()   // 기본 거부

// CSRF: SSE/MCP 경로만 선택적 무시
.csrf(csrf -> csrf
    .ignoringRequestMatchers("/sse", "/mcp/**")
)
```

**영향 범위**
`SecurityConfig.java`, `chat.html` (CSRF 토큰 전송 로직 추가 필요)

## 4. API Key 기본값 🟡

**대상 파일**
- `src/main/java/com/krdevops/springai/config/AppProperties.java:15`
- `src/main/resources/application.yaml:83`

**현재 코드**
```java
// AppProperties.java:15
private String apiKey = "local-dev-key";
```
```yaml
# application.yaml:83
app:
  api-key: ${APP_API_KEY:local-dev-key}
```

**문제 시나리오**
- `APP_API_KEY` 환경변수 미설정 시 예측 가능한 `"local-dev-key"`로 인증 동작
- `/api/tools/**` 엔드포인트 인증 무력화
- 노출 대상: DB 스키마 조회, 파일 저장, 직원정보 수정 등 민감 기능

**수정 방향**
```java
// AppProperties.java
@NotBlank
private String apiKey;  // 기본값 제거
```
```yaml
# application.yaml
app:
  api-key: ${APP_API_KEY}  # 기본값 제거 → 미설정 시 기동 실패
```

**영향 범위**
`AppProperties.java`, `application.yaml` 단일 설정

## 5. VectorStore URI 수동 파싱 🟡

**대상 파일**
- `src/main/java/com/krdevops/springai/config/VectorStoreConfig.java:32-36`

**현재 코드**
```java
String uri = redisUri.replace("redis://", "");
String[] parts = uri.split(":");
String host = parts[0];
int port = parts.length > 1 ? Integer.parseInt(parts[1]) : 6379;
return new JedisPooled(host, port);
```

**문제 시나리오**
- `rediss://` (TLS) URI → `replace("redis://", "")` 후 `s://host:port` 파싱 실패
- `redis://user:password@host:port` → `split(":")` 오분할
- 운영 환경에서 Redis 인증/TLS 추가 시 **즉시 애플리케이션 기동 실패**

**수정 방향**
```java
// 한 줄로 교체
return new JedisPooled(URI.create(redisUri));
```

**영향 범위**
`VectorStoreConfig.java` 단일 파일, `jedisPooled()` 빈 1개
