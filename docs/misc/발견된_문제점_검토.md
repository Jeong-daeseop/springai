## 1. 실제 확인된 문제점

### 🔴 P1 — API Key NPE

- **위치**: `src/main/java/com/krdevops/springai/config/SecurityConfig.java:76`
- **코드**:
  ```java
  if (appProperties.getApiKey().equals(key)) {
  ```
- **문제**: `APP_API_KEY` 환경변수 미설정 시 `getApiKey()` 가 `null` 반환 → `NullPointerException` 으로 서버 크래시
- **근거**: `AppProperties.java:15` — `private String apiKey;` (기본값 없음)
- **수정 방향**: `key != null && key.equals(appProperties.getApiKey())` 로 변경

---

### 🔴 P1 — DB 계정 하드코딩

- **위치**: `src/main/resources/application.yaml:54-55`
- **코드**:
  ```yaml
  username: com
  password: com01
  ```
- **문제**: DB 계정 정보가 소스코드에 평문으로 노출 (eGov 보안 규칙 위반)
- **수정 방향**:
  ```yaml
  username: ${DB_USERNAME:com}
  password: ${DB_PASSWORD:com01}
  ```

---

### 🟡 P2 — OllamaConfig temperature 충돌

- **위치**: `src/main/java/com/krdevops/springai/config/OllamaConfig.java:56` vs `src/main/resources/application.yaml:44`
- **코드**:
  ```java
  // OllamaConfig.java:56
  .temperature(0.3)
  ```
  ```yaml
  # application.yaml:44
  temperature: 0.0
  ```
- **문제**:
  - 수동 빈(`OllamaConfig`)이 Spring AI 자동설정을 덮어씀
  - YAML의 `num-predict: 2048`, `num-ctx: 8192` 설정이 **무시됨**
  - temperature 0.3 (수동) vs 0.0 (YAML) 불일치
- **수정 방향**: `OllamaConfig.java` 삭제 → Spring AI 자동설정으로 전환 (YAML 설정 일원화)

---

### 🟡 P2 — JSP 템플릿 XSS 취약점

- **위치**: `src/main/java/com/krdevops/springai/service/CrudPromptBuilderService.java:335`
- **코드**:
  ```java
  sb.append("                                <td>${item.").append(field).append("}</td>\n");
  ```
- **문제**: 생성된 JSP에서 `${item.field}` 직접 출력 → XSS 취약 (eGov 보안 규칙 위반)
- **수정 방향**:
  ```java
  sb.append("                                <td><c:out value=\"${item.").append(field).append("}\"/></td>\n");
  ```

---

### 🟡 P2 — @CrossOrigin 무제한 허용

- **위치**: `src/main/java/com/krdevops/springai/chat/controller/EgovDocumentController.java:17`
- **코드**:
  ```java
  @CrossOrigin
  ```
- **문제**: `origins` 미지정 → 모든 도메인에서 문서 업로드/재인덱싱 API 호출 가능
- **수정 방향**:
  ```java
  @CrossOrigin(origins = "${app.allowed-origins:http://localhost:8080}")
  ```

---

### 🟡 P3 — LLM 라우팅 이중 구조

- **위치 A**: `src/main/java/com/krdevops/springai/service/LlmRouterService.java`
- **위치 B**: `src/main/java/com/krdevops/springai/chat/service/impl/EgovSessionAwareChatServiceImpl.java:52`
- **문제**:
  - `LlmRouterService` (REST API용): taskType 기반, `ChatModel.call()` 직접 호출 — 스트리밍/메모리/RAG 없음
  - `selectClient()` (웹 채팅용): 모델명 접두사 기반, `ChatClient` 사용 — 스트리밍/메모리/RAG 포함
  - 두 메커니즘이 완전 독립적으로 진화, 동기화 불가
  - `LlmRouterService.chat()` 에서 `CLAUDE` taskType은 예외를 던짐 (실제 Claude 호출 불가)
- **수정 방향**: `LlmRouterService` 를 `ChatClient` 반환 방식으로 개선하여 단일화

---

### 🟢 P4 — 존재하지 않는 OpenAI 모델명

- **위치**: `src/main/resources/application.yaml:85-86`
- **코드**:
  ```yaml
  openai-models:
    - gpt-5.4-mini
    - gpt-5.4
  ```
- **문제**: OpenAI API에 존재하지 않는 모델명 → 실제 호출 시 오류 발생
- **수정 방향**: `gpt-4o-mini`, `gpt-4o` 등 실제 존재하는 모델명으로 교체
