## 추가 권장 항목 (28개)

### 1. 복합 생성 프롬프트 빌더 (우선순위 최상)

**Tool:** `buildFullCrudPrompt(database, tableName, domain, packageName, outputPath)`

**목적:**
테이블명 하나 입력 시 전체 레이어(10개 파일) 생성에 필요한 정보를 한 번에 조합한
프롬프트를 반환하여 Claude가 자동으로 전체 소스를 생성하도록 한다.

**현재 문제:**
- Claude가 getTableSchema → getCodeTemplate × 10 → saveGeneratedCode × 10
  → validateGeneratedCode → saveGenerationHistory 순서를 매번 수동으로 진행해야 함
- 사용자가 단계별로 지시해야 하는 번거로움 존재

**해결:**
- 이 Tool 하나만 호출하면 스키마 + 공통코드 + 템플릿 가이드를 묶어 Claude에게 전달
- 생성 단계 자동화, 사용자 개입 최소화

**구현 위치:** 신규 tools/CrudPromptBuilderTool.java, service/CrudPromptBuilderService.java

### 2. 테이블 연관 관계 분석

**Tool:** `getTableRelations(database, tableName)`

**목적:**
FK, JOIN 관계를 파악하여 연관 테이블과 함께 소스 생성 시 참조 정보를 제공한다.

**반환 정보:**
- 이 테이블을 참조하는 테이블 목록 (부모 → 자식)
- 이 테이블이 참조하는 테이블 목록 (자식 → 부모)
- 추천 JOIN 쿼리 패턴

**활용:**
- 마스터-디테일 구조 소스 자동 생성
- 공통 코드 테이블 JOIN이 필요한 VO/Mapper 자동 생성
- 복잡한 화면(다중 테이블 조회) 대응

**구현 위치:** 신규 메서드 추가 또는 별도 Tool

### 10. 보안 취약점 검사

**Tool:** `scanSecurityVulnerability(filePath)`

**목적:**
생성된 소스에서 eGovFrame/행안부 보안 가이드 기준의 취약점 패턴을 검사한다.

**검사 항목:**
- SQL Injection: 동적 쿼리에 직접 파라미터 삽입 여부
- XSS: JSP에서 ${param.*} 직접 출력 여부 (<c:out> 미사용)
- CSRF: form POST에 토큰 처리 여부
- 경로 조작: 파일 경로에 사용자 입력 직접 사용 여부
- 민감 정보 노출: 주석/로그에 비밀번호·키 포함 여부

**활용:** 생성 → 표준 검증 → 보안 검사 → 배포 파이프라인 완성

**구현 위치:** service/CodeValidatorService.java 확장 또는 신규 tools/SecurityScannerTool.java

### 14. ERD 텍스트 생성

**Tool:** `generateErd(database, tableNames)`

**목적:**

**반환 예시:**
  COMTNEMPLYRINFO
    ├── EMPLYR_ID (PK, VARCHAR(20))
    ├── USER_NM (VARCHAR(50))
    ├── OFCPS_NM (VARCHAR(100))
    └── EMPLYR_STTUS_CODE → COMTCCMMNDETAILCODE.CODE (FK)

  COMTCCMMNDETAILCODE
    ├── CODE_ID (PK, VARCHAR(6))
    └── CODE (PK, VARCHAR(15))

**활용:**
- 소스 생성 전 테이블 구조 한눈에 파악
- 설계 문서 자동 생성
- 연관 관계 분석(2번) 결과 시각화

**구현 위치:** 신규 tools/ErdGeneratorTool.java, service/ErdGeneratorService.java

### 17. 쿼리 성능 분석

**분석 항목:**

- 동적 쿼리의 인덱스 미활용 가능성

**활용:** 생성된 Mapper XML 품질 검증, 운영 배포 전 성능 사전 점검

**구현 위치:** 신규 tools/QueryAnalyzerTool.java, service/QueryAnalyzerService.java

### 29. Spring Security 설정 파일 템플릿

**Tool:** `getSecurityTemplate(securityType, packageName)`

securityType: `webXmlFilter` / `contextSecurity` / `javaConfig` / `userDetailsService` / `roleHierarchy` / `loginPage`

**목적:**
eGovFrame 5.x 표준 "혼합형 보안 아키텍처" 설정 파일 템플릿을 반환한다.
Spring Security 엔진 + eGovFrame 공통 권한관리 시스템을 분리하여 이해하고,
공공 SI 레거시 호환성(XML+Session)과 신규 방식(JavaConfig+Session) 모두 지원한다.

**eGovFrame 5.x Security 전체 구조:**
```
[사용자 요청]
      ↓
web.xml → DelegatingFilterProxy
      ↓
springSecurityFilterChain
      ↓
Security Filter Chain
      ↓
AuthenticationManager → UserDetailsService → DB 조회
      ↓
SecurityContext → HttpSession 저장
      ↓
Controller 접근 허용
```

**Spring Security 엔진 vs eGovFrame 권한관리 구분:**
- Spring Security → 인증 엔진 (Filter Chain, AuthenticationProvider)
- eGovFrame 권한관리 → 공공 업무 권한 시스템 (사용자/부서/그룹/메뉴/URL 권한)

**반환 내용:**

- `webXmlFilter`: web.xml DelegatingFilterProxy 설정
  - `springSecurityFilterChain` 필터 등록
  - `/*` 전체 URL 가로채기
  - 레거시 공공 SI 호환 구조

- `contextSecurity`: context-security.xml (레거시 XML 방식)
  - `<http>` 인터셉터 URL 패턴 설정
  - DB 기반 `FilterInvocationSecurityMetadataSource` 설정
  - `<form-login>` / `<logout>` 표준 설정
  - `EgovAccessDeniedHandler` 연동
  - Session 기반 SecurityContext 유지

- `javaConfig`: EgovSecurityConfig.java (신규 Java Config 방식)
  - `@EnableWebSecurity` + `SecurityFilterChain` Bean
  - `HttpSecurity` DSL 기반 URL 접근 제어
  - Session 기반 인증 유지 (`SessionCreationPolicy.IF_REQUIRED`)
  - CSRF 설정 (JSP Form 기반이므로 활성화)
  - `RoleHierarchyImpl` 빈 등록

- `userDetailsService`: EgovUserDetailsServiceImpl.java
  - `UserDetailsService` 구현체
  - COMTNEMPLYRINFO 기반 사용자 조회
  - COMTNEMPLYRSCRTYESTBS 기반 AUTHOR_CODE 조회
  - `GrantedAuthority` 목록 반환

- `roleHierarchy`: RoleHierarchy 설정
  - COMTNROLES_HIERARCHY 테이블 기반 계층 구성
  - ROLE_ADMIN > ROLE_USER > ROLE_ANONYMOUS 자동 상속
  - `RoleHierarchyImpl` 빈 설정 코드

- `loginPage`: login.jsp
  - eGovFrame 표준 로그인 폼 (`/uat/uia/egovLoginUsr.do`)
  - CSRF 토큰 처리
  - 로그인 실패 메시지 처리

**실무 패턴별 지원:**

| 방식 | 사용률 | 지원 |
|---|---|---|
| XML + Session (공공 레거시) | 매우 많음 | ✅ contextSecurity |
| Java Config + Session (유지보수) | 증가 중 | ✅ javaConfig |
| JWT + REST API (MSA) | 증가 중 | 별도 항목 |
| OAuth2/SSO (대형기관) | 대형기관 | 별도 항목 |

**활용:**
- 신규 eGovFrame 5.x 프로젝트 Security 초기 설정 자동화
- `generateAuthInsertSql()` 로 등록한 COMTNROLEINFO 데이터와 연동
- 레거시 XML → Java Config 전환 시 참조 템플릿

**관련 DB 테이블:**
- `COMTNROLEINFO` — URL 패턴(정규식) + ROLE_CODE
- `COMTNAUTHORROLERELATE` — AUTHOR_CODE ↔ ROLE_CODE N:N 매핑
- `COMTNEMPLYRSCRTYESTBS` — 사용자 ↔ AUTHOR_CODE 매핑
- `COMTNROLES_HIERARCHY` — 권한 계층 구조 (PARNTS_ROLE → CHLDRN_ROLE)

**관련 Tool:**
- `generateAuthInsertSql()` — COMTNROLEINFO / COMTNAUTHORROLERELATE 데이터 등록
- `getConfigTemplate("contextCommon")` — 기본 Spring 설정

**구현 위치:** 신규 tools/SecurityTemplateTool.java, service/SecurityTemplateService.java
