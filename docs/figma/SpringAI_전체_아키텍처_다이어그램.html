SpringAI · eGovFrame MCP 서버

프로젝트 전체 아키텍처

Spring Boot 단일 서버가 /mcp(Streamable HTTP)와 /api/**(REST) 두 진입점을 같은 서비스 계층으로 연결하고, Figma 디자인 시스템과 로컬 Thymeleaf/JSP 화면을 별도 Node.js 서브 프로젝트 6개가 JSON 계약으로 오가며 동기화합니다.

1. 런타임 요청 흐름

MCP Tool 호출과 REST 호출이 같은 Application/Generation 서비스로 합류하되, 인가 경로는 다릅니다.

2. 생성 파이프라인과 지원 자산

화면 하나를 만드는 데 관여하는 Figma 파이프라인과 코드 생성 Tool 체인, 그리고 이것들과는 완전히 독립된 채팅(RAG) 기능을 한 섹션에 모았습니다. 세 개의 하위 다이어그램은 서로 다른 관심사를 다루므로 개별적으로 읽으십시오.

2.1 Figma ↔ Thymeleaf 디자인 파이프라인

Figma 파일을 허브로, 읽기(디자인→코드)·캡처(코드→디자인 재현)·내보내기·토큰 동기화 네 갈래가 별도 Node.js 프로젝트를 오갑니다.

2.2 코드 생성 Tool 오케스트레이션

화면 하나를 만들기까지 사람이 순서대로 호출해야 하는 MCP Tool 체인입니다. 아래는 파일 위치가 아니라 Tool 실행 순서와 서로의 전제 조건을 보여줍니다 — 특히 1·2단계는 같은 layout 파일 경로를 두고 "정적 골격 → 동적 업그레이드" 관계로 순서가 강제됩니다.

2.3 RAG / Chat 흐름

Figma·Thymeleaf 생성과는 완전히 독립된 별도 기능입니다. Ollama·OpenAI 채팅에 Redis 기반 RAG를 결합합니다.

3. Component Catalog / Registry 계약 진화 — v1 → v2 → v3

"무엇을 어떻게 그릴지"를 정의하는 디자인 시스템 계약 자체가 겪은 SSOT(단일 진실 공급원) 마이그레이션입니다. Catalog와 Registry가 각자 다른 속도로 버전업하며 v1 → v2 → v3로 이어집니다(18~20번 문서).

4. Q&A Runtime Resolver 상세 — 현재 Legacy(v2 Registry) 경로

3번 다이어그램의 "Q&A Runtime Resolver" 박스를 펼친 6단계입니다. 지금 실제로 도는 경로이므로 Registry는 Legacy v2, 반면 화면 입력(Q&A 7개 업무 화면 fixture)은 ScreenSpecification 자체 기준 v3입니다 — 3번 다이어그램의 Catalog/Registry v1~v3와는 별개의 버전 축입니다. 결정론적 재현성이 핵심이라 동일 입력을 두 번 해석해도(ResolutionResult) 같은 Rule ID·Context Hash가 나오는지 테스트로 강제합니다(KrdsQnaRuntimeResolverIntegrationTest).

5. Spring MCP 서버 상세 — DesignReferenceTool

2번 다이어그램의 5번 배지를 펼친 내부 흐름입니다. DB 매핑 난이도에 따라 "즉시 승인" 또는 "사람 확인 필요"로 갈라집니다.

6. Thymeleaf 생성 서비스 상세

2번 다이어그램의 6번 배지를 펼친 내부 흐름입니다. layout은 프로젝트당 한 번만 만들고 재사용합니다.

7. 로컬 화면 상세 — eGovFrame 4계층

2번 다이어그램의 7번 배지를 펼친 것입니다. 이 박스는 springai가 만들어낸 코드가 실행되는 "결과물"이라, 흐름이 아니라 계층 구조를 보여줍니다.

8. jsp-design-extractor 상세

2번 다이어그램의 8번 배지를 펼친 내부 흐름입니다(05_Overall_Architecture_Diagram.md의 E1~E4 단계와 대응).

9. component-contracts 상세 — 디자인 토큰 구조

2번 다이어그램의 9번 배지를 펼친 내부 구조입니다. W3C Design Tokens 형식($value/$type)을 따르며, Primitive를 Semantic이 참조합니다.

10. krds-design-system-author-plugin 상세

2번 다이어그램의 10번 배지를 펼친 내부 흐름입니다. 마지막 단계는 3번 다이어그램의 "Registry (Legacy)"로 이어집니다.

11. jsp-to-figma-plugin 상세

2번 다이어그램의 11번 배지(및 8번 다이어그램 출력)를 펼친 내부 흐름입니다. 네트워크에 접근하지 않는 로컬 전용 Plugin이며 실패 시 이번 실행분만 롤백합니다.
