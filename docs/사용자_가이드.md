# SpringAI 사용자 가이드

> 정본 사용자 문서  
> 기준일: 2026-08-03  
> MCP 계약 기준: 92개 Tool 메서드 / 34개 Tool 객체

이 문서는 SpringAI MCP 서버를 처음 설치하고, Claude Desktop/Web 또는 MCP 클라이언트에서 eGovFrame·Thymeleaf·Figma 기능을 사용하는 방법을 설명합니다.

## 1. 제공 기능

- eGovFrame CRUD·Board·Master-detail 코드 생성
- DB 스키마·공통코드·메뉴 조회
- JSP/화면 분석과 Thymeleaf 화면 생성
- Figma Screen Specification·Design System·Export Bundle 처리
- 승인 기반 Project Preview·Apply·Rollback
- 실제 Artifact 기반 디자인 parity 검증
- Ollama·OpenAI 채팅과 Redis RAG 문서 검색

## 2. 실행 환경

필수 환경:

- JDK 17 이상(개발 권장 JDK 21)
- MySQL 8 및 `egov-mysql` 컨테이너
- Redis Stack
- Ollama
- ONNX 임베딩 모델(`model.onnx`, `tokenizer.json`)

의존 서비스 시작:

```bash
docker start egov-mysql
ollama serve
ollama pull qwen3:8b
ollama pull qwen3:1.7b
```

Redis 기본 주소는 `redis://localhost:6379`입니다.

## 3. 환경변수

```bash
cp .env.example .env
```

`.env`는 Spring Boot가 자동으로 읽지 않으므로 IDE Run Configuration이나 셸에 주입해야 합니다.

최소 실행 설정:

```bash
export OPENAI_API_KEY=...
export MCP_SHARED_TOKEN='충분히 긴 무작위 token'
export MCP_AUTH_MODE=REQUIRED
export ONNX_MODEL_PATH=/path/to/model.onnx
export ONNX_TOKENIZER_PATH=/path/to/tokenizer.json
```

주요 설정:

| 변수 | 기본값 | 용도 |
|---|---|---|
| `MCP_SHARED_TOKEN` | 없음 | MCP 공통 transport 인증 |
| `MCP_AUTH_MODE` | `REQUIRED` | `AUDIT_ONLY`, `COMPATIBILITY`, `REQUIRED` |
| `MCP_PREVIOUS_SHARED_TOKEN` | 없음 | token 회전 중 이전 token |
| `MCP_PREVIOUS_TOKEN_VALID_UNTIL` | 없음 | 이전 token UTC 만료 시각 |
| `MCP_LEGACY_CREDENTIAL_VALID_UNTIL` | 없음 | 기존 Tool secret 호환 만료 시각 |
| `SERVER_ADDRESS` | `127.0.0.1` | 외부 bind 주소 |
| `DB_USERNAME`/`DB_PASSWORD` | `ebt`/`ebt01` | MySQL 계정 |
| `REDIS_URI` | `redis://localhost:6379` | Redis 주소 |
| `EGOV_OUTPUT_PATH` | 기본 경로 | 생성 파일 출력 경로 |
| `FIGMA_ACCESS_TOKEN` | 없음 | Figma REST API token |

## 4. 서버 실행

```bash
./gradlew bootRun
```

- 웹 서버: `http://localhost:8080`
- MCP Streamable HTTP: `http://localhost:8080/mcp`
- 채팅 UI: `http://localhost:8080/chat` (프로젝트 설정에 따라 제공)

실행 가능한 JAR:

```bash
./gradlew bootJar
java -jar build/libs/springai-0.0.1-SNAPSHOT.jar
```

## 5. MCP 연결과 보안

MCP 요청에는 다음 헤더가 필요합니다.

```http
X-MCP-Token: <MCP_SHARED_TOKEN>
```

프로젝트 MCP 클라이언트 별칭은 `springai-mcp`로 통일합니다. 다른 설정에 `egovframe-mcp`가 남아 있으면 동일한 `/mcp` endpoint가 두 이름으로 표시될 수 있으므로 제거하십시오.

보안 규칙:

- `/api/**`: `X-API-Key` 인증
- `/mcp`, `/mcp/**`, `/sse`, `/sse/**`: MCP token 인증
- 인증 성공 후 Tool 위험 등급별 인가
- 인증 실패 시 Tool 실행·DB·파일·외부 API 호출 차단
- token·secret·API key·fileKey는 로그와 응답에서 마스킹
- 비-loopback `SERVER_ADDRESS`에서는 token과 `MCP_AUTH_MODE=REQUIRED`가 필수

token 회전·호환 모드·실패 코드의 운영 절차는 [WP1 MCP 보안 Runbook](architecture/security/ARCH-WP1-MCP-보안-운영-Runbook.md)을 따릅니다.

## 6. 대표 사용자 workflow

### 6.1 CRUD 생성

1. 대상 DB와 테이블을 확인합니다.
2. `SchemaReaderTool`로 테이블 구조를 조회합니다.
3. CRUD·Board·Master-detail 생성 Tool을 호출합니다.
4. `viewType=thymeleaf` 사용 시 필요한 layout을 먼저 준비합니다.
5. 생성 결과를 검토한 뒤 출력 경로에 저장합니다.
6. 생성 코드 검증과 대상 프로젝트 빌드를 수행합니다.

예시 요청:

```text
COMTNEMPLYRINFO 테이블 기준으로 Employee CRUD를 생성해줘.
eGovFrame 5.0, Thymeleaf, 기존 프로젝트 경로는 /path/to/project야.
먼저 스키마를 확인하고 생성 결과를 저장하기 전에 파일 목록을 보여줘.
```

생성 파일을 실제 프로젝트에 반영하는 경우 승인 기반 Preview→Approve→Apply 절차를 사용합니다.

### 6.2 Thymeleaf Project Apply

권장 순서:

```text
1. Preview 생성
2. Preview hash와 변경 파일 검토
3. 승인(actor + expected hash)
4. source/DESIGN.md revision 재검증
5. Apply
6. render·route·binding·build 검증
7. 실패 시 rollback
```

승인 전에는 대상 프로젝트 파일이 변경되지 않아야 합니다. Preview hash나 source revision이 달라지면 Apply는 거부됩니다.

### 6.3 Figma 연동

1. Figma 파일·페이지·editable scope를 확인합니다.
2. Screen Specification 또는 Design System을 준비합니다.
3. Figma Export/Design System 검증 Tool을 실행합니다.
4. Bundle·Artifact·validation report를 확인합니다.
5. 사람 승인 후 Apply 또는 Plugin 연계를 진행합니다.

Figma Library Publish, 공개 Component Key 변경, 범위 밖 노드 수정은 자동으로 수행되지 않습니다.

### 6.4 RAG 문서 검색

1. 문서 또는 URL을 등록합니다.
2. Redis VectorStore indexing 완료를 확인합니다.
3. 자연어로 eGovFrame 문서를 검색합니다.
4. 검색 결과의 출처와 문서 버전을 확인합니다.

## 8. 문제 해결

### MCP 인증 실패

- `MCP_SHARED_TOKEN`이 서버에 주입됐는지 확인합니다.
- 클라이언트 요청의 `X-MCP-Token`이 동일한지 확인합니다.
- 오류 코드가 `MCP_TOKEN_MISSING`, `MCP_TOKEN_INVALID`, `MCP_TOKEN_EXPIRED` 중 무엇인지 확인합니다.
- 비-loopback 서버라면 `MCP_AUTH_MODE=REQUIRED`인지 확인합니다.

### 서버 기동 실패

- MySQL·Redis·Ollama가 실행 중인지 확인합니다.
- `OPENAI_API_KEY`, ONNX model/tokenizer 경로를 확인합니다.
- 로그의 Bean 생성 오류와 환경변수 placeholder 오류를 먼저 확인합니다.

### MCP 연결 상세 오류

[MCP 연결 오류 해결 가이드](misc/MCP_연결_오류_해결_가이드.md)는 과거 연결 장애 사례를 보관한 참고 문서입니다. 현재 endpoint와 인증 방식은 이 문서와 [WP1 Runbook](architecture/security/ARCH-WP1-MCP-보안-운영-Runbook.md)을 우선합니다.
