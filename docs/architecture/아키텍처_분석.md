# 프로젝트 아키텍처 분석

Spring Boot 4.0.6 + Spring AI 2.0.0-M8 기반 eGovFrame 5.x CRUD 소스 자동 생성 AI 플랫폼

---

## 1. 시스템 정의

단일 애플리케이션 안에 두 가지 역할이 공존합니다:

- **MCP Server** — Claude Desktop과 SSE 트랜스포트로 연결되어, Claude가 `@Tool` 메서드를 직접 호출하여 DB 스키마 조회, 코드 생성, RAG 검색 등을 수행
- **Web Chat UI** — Thymeleaf 기반 채팅 인터페이스에서 Ollama/OpenAI를 직접 호출하여 RAG 기반 Q&A 제공

---

## 2. 기술 스택

| 계층 | 기술 |
|------|------|
| Runtime | Spring Boot 4.0.6, Java 17 |
| AI Framework | Spring AI 2.0.0-M8 (MCP Server WebMVC, OpenAI, Ollama, Transformers) |
| LLM | Claude (MCP SSE), OpenAI (gpt-4o-mini), Ollama (qwen3:8b) |
| 임베딩 | ko-sroberta-multitask ONNX (로컬, 768차원) |

| 데이터 접근 | JdbcTemplate (Spring Boot 4.x에서 MyBatis 미지원) |
| 세션/메모리 | Redis (ChatMemory + 세션 저장) |
| 보안 | Spring Security 6.x (API Key 인증, Stateless) |
| 뷰 | Thymeleaf 3.x |
| 빌드 | Gradle |

## 5. 데이터 흐름

### 경로 A: Claude Desktop (MCP SSE)

```
Claude Desktop
  │ SSE (HTTP /sse + /mcp/**)
  ▼
spring-ai-starter-mcp-server-webmvc  (JSON-RPC 디스패처)
  │ @Tool 메서드 자동 라우팅
  ▼
*Tool 클래스
  ├─→ SchemaService → JdbcTemplate → MySQL
  ├─→ CrudPromptBuilderService (프롬프트 조립)
  ├─→ CodeService.generateSource() (템플릿 치환)
  ├─→ CodeService.saveGeneratedCode() (파일 저장)
  └─→ CodeValidatorService (구조 검증)
  ▼
Claude Desktop ← Tool 반환값
```

**llmProvider 분기:**
- `"claude"` — 프롬프트만 반환, Claude가 11개 Tool을 순차 호출
- `"auto"` — Tool 내부에서 11개 파일 직접 생성/저장 (Claude 토큰 97% 절감)

### 경로 B: Web Chat UI

```
브라우저 (chat.html)
  │ SSE GET /ai/rag/stream?message=...&model=...&sessionId=...
  ▼
EgovOllamaChatController
  ├─→ EgovCompressionQueryTransformer (쿼리 압축, qwen3:1.7b)
  ├─→ ContextAssembler (DB 스키마+이력+관계, 6,000자 예산)
  ├─→ EgovPromptBuilder (시스템 프롬프트)
  ▼
EgovSessionAwareChatServiceImpl
  ├─→ selectClient(model)  gpt-* → OpenAI / 기타 → Ollama
  ├─→ QuestionAnswerAdvisor  (VectorStore 자동 검색)
  ├─→ MessageChatMemoryAdvisor  (Redis, 8메시지 윈도우)
  ▼
Flux<ChatResponse> → SSE → 브라우저
```

## 7. RAG 파이프라인

### 임베딩 (Ingestion)

```
입력 소스 (텍스트/URL/.java/PDF)
  → ChunkService (700자 단위, 100자 overlap, 자연경계 분할)
  → ko-sroberta-multitask ONNX 임베딩 (로컬, 512 토큰)
  → Redis VectorStore (메타데이터: type, docId)
```

**청크 관리:** 동일 docId 재임베딩 시 구 청크 삭제 후 새 청크 저장 (`chat:chunk-ids:{docId}` 키로 추적)

### 검색 (Retrieval)

| 경로 | 메커니즘 | 설정 | 용도 |
|------|----------|------|------|
| QuestionAnswerAdvisor | Spring AI Advisor 자동 검색 | threshold=0.30, topK=10 | Web Chat RAG |
| RagService.search() | 수동 호출 | 범용 | MCP Tool 직접 사용 |

## 9. 설계 강점

| 항목 | 내용 |
|------|------|
| 3-LLM 하이브리드 | 작업 특성별 LLM 선택으로 비용/품질/보안 최적화 |
| auto 모드 | LLM 개입 없이 결정적 생성 → 토큰 97% 절감 |
| 로컬 ONNX 임베딩 | 한국어 특화, 외부 API 무의존 |
| 토큰 예산 관리 | ContextAssembler 6,000자 예산 내 우선순위 조립 |
| 보안 템플릿 버전 분기 | eGovFrame 4.3/5.0, XML/JavaConfig 정확히 분리 |
| 자연경계 청킹 | 줄바꿈 → 문장부호 → 공백 순 후방 탐색으로 문맥 손실 최소화 |

## 10. 개선 포인트

| 우선순위 | 항목 | 상태 | 내용 |
|----------|------|------|------|
| 🔴 High | API Key 기본값 | ✅ 완료 | `"local-dev-key"` 하드코딩 제거 → `${APP_API_KEY}` 환경변수 필수화 |
| 🔴 High | SessionContext ThreadLocal | ✅ 완료 | `SessionContext` 클래스 삭제, `sessionId`를 메서드 파라미터로 직접 전달 |
| 🟡 Medium | McpConfig 반복 코드 | ✅ 완료 | 19개 개별 빈 → 단일 `allToolCallbacks` 빈으로 통합 (130줄→25줄) |
| 🟡 Medium | CSRF 전면 비활성화 | ✅ 완료 | `/sse`, `/mcp/**`만 CSRF ignore, 나머지 활성화 + chat.html csrfHeaders() 추가 |
| 🟢 Low | VectorStore URI 파싱 | ✅ 완료 | `URI.create(redisUri)` 방식으로 변경, TLS(`rediss://`) 및 인증 URI 지원 |
| 🟡 Medium | LLM 라우팅 이중 구조 | 🔲 미완료 | `LlmRouterService` vs `selectClient()` 역할 중복 정리 필요 |

## 11. Trade-offs 요약

| 설계 선택 | 장점 | 단점 |
|-----------|------|------|
| 3-LLM 하이브리드 | 비용/품질/보안 최적화 | 운영 복잡도 증가, 장애 포인트 3배 |
| auto 모드 (결정적 생성) | 토큰 97% 절감, 일관된 품질 | 커스터마이징 유연성 감소 |
| 로컬 ONNX 임베딩 | 비용 0, 한국어 특화 | 대량 임베딩 시 속도 느림 (GPU 없을 경우) |
| Redis 통합 (VectorStore + ChatMemory + 세션) | 인프라 단순화 | Redis 단일 장애점 |
| 메서드 파라미터 세션 전파 | Reactor 안전, 명시적 | 메서드 시그니처 변경 필요 |
