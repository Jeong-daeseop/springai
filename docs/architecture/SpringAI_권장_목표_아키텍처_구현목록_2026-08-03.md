## 1. 상태 표기와 운영 규칙

| 표기 | 의미 |
|---|---|
| `[ ]` | 미착수 |
| `[-]` | 진행 중 |
| `[x]` | 구현과 완료 Gate 검증 완료 |
| `[!]` | 차단 또는 별도 결정 필요 |
| `[~]` | 코드 존재, 완료 Gate 미충족 |

운영 규칙:

- 클래스나 메서드가 존재한다는 이유만으로 `[x]`로 변경하지 않는다.
- 각 항목은 연결된 단위·통합·계약 테스트 또는 운영 증적이 있어야 완료된다.
- 상태 변경 시 증적 열 또는 작업 기록에 test/report/commit을 남긴다.
- 기존 코드에 일부 구현이 있어도 이 목록의 Gate를 다시 확인하기 전에는 `[~]` 또는 `[ ]`로 둔다.
- P0 항목이 `[!]`인 상태에서는 Release Gate를 승인하지 않는다.
- 이 문서는 전체 아키텍처의 집계 상태 원장이다. Figma·Thymeleaf 상세 원장의 개별 `[x]`가 있어도
  이 문서의 상위 완료 Gate가 열려 있으면 집계 상태는 `[~]`를 유지한다.

### 1.1 실행 승인 조건

- [x] 작업표와 Mermaid 선행조건이 일치한다.
- [x] WP2A 긴급 격리와 WP2B 안전 재구현이 분리됐다.
- [x] WP1 인증 위치를 `OncePerRequestFilter` + `RiskAwareToolCallbackProvider`로 확정했다.
- [x] dirty code fingerprint와 MCP snapshot hash를 구현계획서 §0.1에 기록했다.
- [x] multi-project 적용 여부와 WP2B 재구현 여부를 ADR로 종료할 수 있다.
- [x] 동시 리팩터링 파일의 stage·commit은 소유권 확정 전 금지한다.

이 승인은 계획 실행에 대한 승인이다. 현재 미커밋 코드 전체를 한 번에 stage하거나 commit하는 승인이
아니다.
