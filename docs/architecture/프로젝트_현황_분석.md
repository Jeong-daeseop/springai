# 프로젝트 현황 분석

> 분석일: 2026-06-17  
> 기준 버전: Spring Boot 4.1.0-RC1 / Spring AI 2.0.0-RC1

---

## 1. 프로젝트 개요

**eGovFrame 5.x 전용 AI 개발 도우미 MCP 서버.**  
Claude Desktop이 JSON-RPC로 호출할 수 있는 MCP Tool 20개를 제공하며,  
eGovFrame 프로젝트 골격 생성 · CRUD 소스 자동 생성 · 보안 설정 생성 · RAG 기반 문서 검색을 담당한다.

## 3. 아키텍처 개요

```
Claude Desktop
    │  JSON-RPC  (Streamable HTTP, port 8080)
    ▼
┌─────────────────────────────────────────────┐
│  MCP Tool 레이어  (tools/ — 20개 @Tool)      │
└──────────────┬──────────────────────────────┘
               │
    ┌──────────┼──────────────┐
    ▼          ▼              ▼
Service     Service       Service
initializr  security      chat/rag
(프로젝트    (보안 설정     (문서 검색
 골격 생성)   파일 생성)     + 채팅 메모리)
    │          │              │
    ▼          ▼              ▼
 FreeMarker   .tpl         Redis VectorStore
 템플릿        템플릿        + Ollama / OpenAI
               │
               ▼
          MySQL (egov-mysql)
          eGovFrame 공통 테이블
```

### 처리 흐름 (CRUD 자동 생성)

```
Claude → SchemaReaderTool (스키마 조회)
       → CrudPromptBuilderTool (프롬프트 조립)
       → [Claude가 코드 생성]
       → CodeValidatorTool (검증)
       → CodeSaverTool (파일 저장)
```

### 처리 흐름 (RAG 검색)

```
사용자 질문
    → qwen3:1.7b (쿼리 압축)
    → ko-sroberta ONNX (임베딩)
    → Redis 유사도 검색 (threshold=0.30, top-k=10)
    → 컨텍스트 주입 → Ollama qwen3:8b (응답 생성)
```

## 5. 핵심 설계 패턴

### 5.1 FilePlan 패턴

파일 생성 작업을 계획(plan)과 실행(execute)으로 분리한다.

```java
// FilePlan = (상대경로, 파일종류, 내용공급자)
FilePlan.of("src/main/resources/application.yml", RESOURCE, () -> stpl.applicationYml(s))
```

`FilePlanFactory`(프로젝트 초기화)와 `SecurityFilePlanFactory`(보안 설정) 모두 이 패턴을 따른다.  
`FilePlanExecutor`가 목록을 받아 실제 파일 I/O를 수행한다.

### 5.2 VersionCapability 전파

eGovFrame 버전 선택 시 `VersionCapability` 레코드가 생성되고,  
`ProjectSpec` / `SecuritySpec`을 통해 모든 템플릿 빌더까지 전달된다.

```
egovVersion="5.0"
    → VersionCapability(jakarta=true, spring6=true, java17=true, boot3=true, ...)
    → ProjectSpec
    → FilePlanFactory → BuildFileRenderer / StaticTemplateRenderer
```

버전별 분기가 단일 진입점에서 결정되어 템플릿 코드가 단순해진다.

### 5.3 이중 템플릿 엔진

| 엔진 | 확장자 | 용도 |
|---|---|---|
| FreeMarker | `.ftl` | CRUD 소스 (Controller·Service·Mapper·VO·JSP) |
| 자체 `.tpl` | `.tpl` | 프로젝트/보안 설정 파일 (XML, yml, Java) |

## 7. 주요 설정값 (application.yaml)

```yaml
spring.ai.mcp.server.protocol: STREAMABLE       # HTTP 트랜스포트
spring.ai.ollama.chat.options.model: qwen3:8b   # 기본 생성 모델
spring.ai.ollama.chat.options.temperature: 0.0  # 결정적 출력 (코드 생성)
spring.ai.ollama.chat.options.num-ctx: 8192      # 컨텍스트 윈도우

rag.similarity.threshold: 0.30   # 유사도 임계값
rag.top-k: 10                    # 검색 범위
rag.compression.model: qwen3:1.7b

chat.memory.max-messages: 8      # 슬라이딩 메모리 크기

egov.output.base-path: ~/workspace-egov/egov-generated
```

## 8. 현재 상태 및 주의사항

### 미커밋 변경

| 파일 | 상태 |
|---|---|
| `chat/config/EgovRedisConfig.java` | Modified (미커밋) |

### CLAUDE.md 오기재

CLAUDE.md에 `web-application-type: none` / `transport: stdio`로 명시되어 있으나,  
실제 `application.yaml`은 `web-application-type: servlet` / `protocol: STREAMABLE` (HTTP 8080)로 동작 중.  
문서 수정이 필요하다.

### RC 버전 사용

Spring Boot 4.1.0-RC1 + Spring AI 2.0.0-RC1을 사용 중으로,  
GA 릴리즈 전 API 변경 가능성이 있다.

### Redis 이중 역할

단일 Redis 인스턴스가 RAG 벡터 스토어와 채팅 메모리를 동시에 담당한다.  
운영 환경에서는 분리를 검토할 것.

## 9. 로컬 실행 조건

```bash
# 1. Docker 컨테이너 기동
docker start egov-mysql

# 2. Redis 기동 (로컬 또는 Docker)
redis-server

# 3. Ollama 모델 확인
ollama list   # qwen3:8b, qwen3:1.7b 필요

# 4. 환경변수 설정
export OPENAI_API_KEY=...
export APP_API_KEY=...
export ONNX_MODEL_PATH=~/models/ko-sroberta/model.onnx
export ONNX_TOKENIZER_PATH=~/models/ko-sroberta/tokenizer.json

# 5. 빌드 및 실행
./gradlew bootRun
```
