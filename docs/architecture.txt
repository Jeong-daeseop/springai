--------------------------------------------------------------------------------
1. 전체 구조
--------------------------------------------------------------------------------

  [Claude Desktop / MCP Client]
          │ SSE (Server-Sent Events, port 8080)
          ▼
  [Spring AI MCP Server]  ← spring-ai-starter-mcp-server-webmvc
          │ @Tool 어노테이션 자동 라우팅
          ▼
  [Tool 클래스]  →  [Service]  →  [Repository / JdbcTemplate]  →  [egov-mysql]
                              →  [VectorStore (Redis)]
                              →  [ChatClient (Ollama)]

  [웹 채팅 UI]  →  /ai/rag/stream, /ai/simple/stream (SSE 스트리밍)
                →  ChatClient → OllamaChatModel → Ollama 서버

--------------------------------------------------------------------------------
2. 핵심 설정
--------------------------------------------------------------------------------

  transport: sse              - HTTP SSE로 MCP 통신 (Claude Desktop 연결)
  web-application-type: servlet - Tomcat 기반 HTTP 서버
  embedding: transformers     - 로컬 ONNX 임베딩 사용 (OpenAI API 불필요)
  chat model: ollama/mistral  - 로컬 LLM (기본값, 런타임에 모델 변경 가능)

4. RAG (Retrieval-Augmented Generation) 흐름
--------------------------------------------------------------------------------

  사용자 질문 입력
      │
      ▼
  [EgovOllamaChatController] /ai/rag/stream
      │ sessionId 설정 (SessionContext ThreadLocal)
      ▼
  [EgovSessionAwareChatServiceImpl.streamRagResponse()]
      │
      ├─ (enable-query-compression=true 인 경우)
      │   └─ [EgovCompressionQueryTransformer.compress()]
      │         ChatMemory에서 히스토리 조회
      │         → ChatClient로 "후속 질문 → 독립 질문" 재작성
      │
      ├─ [RagService.buildRagContext(compressedQuery, topK)]
      │         VectorStore.similaritySearch() → 유사 문서 검색
      │         → 문서들을 컨텍스트 문자열로 포맷
      │
      ├─ 컨텍스트 있으면: system prompt에 참고 문서 삽입
      │
      └─ ChatClient.prompt()
              .system("참고 문서 컨텍스트...")  [선택적]
              .user(query)
              .advisors(MessageChatMemoryAdvisor)  ← 대화 히스토리 자동 주입
              .stream().chatResponse()
              → Flux<ChatResponse> SSE 스트리밍

5. 임베딩 모델 (ko-sroberta-multitask ONNX)
--------------------------------------------------------------------------------

  모델 경로 (외부 파일시스템):
    ~/models/ko-sroberta/model.onnx       (422MB, 단일 파일)
    ~/models/ko-sroberta/tokenizer.json   (735KB)

  설정:
    spring.ai.model.embedding: transformers
    spring.ai.embedding.transformer.onnx.modelUri: file:${user.home}/models/ko-sroberta/model.onnx
    spring.ai.embedding.transformer.onnx.modelOutputName: last_hidden_state
    spring.ai.embedding.transformer.tokenizer.uri: file:${user.home}/models/ko-sroberta/tokenizer.json

  특이사항:
    - dynamo=False, opset_version=14 으로 export한 단일 파일 사용
      (dynamo export 시 model.onnx + model.onnx.data 분리 포맷 → ONNX Runtime 오류 발생)
    - JAR에 포함하지 않고 file: URI로 외부 참조

6. 채팅 메모리 (Redis)
--------------------------------------------------------------------------------

  구현: EgovRedisChatMemoryRepository (ChatMemoryRepository 구현)
  저장 형식: Redis String, key = "chat:memory:{conversationId}"
  내용: JSON 직렬화된 메시지 목록 [{messageType, content}, ...]

  세션 메타데이터: Redis Hash, key = "chat:session:{sessionId}:info"
  세션 목록: Redis Set, key = "chat:sessions:list"

  ChatMemory 구현체: MessageWindowChatMemory (maxMessages=20)

7. 보안
--------------------------------------------------------------------------------

  /api/**        → X-API-Key 헤더 검증 (값: ${APP_API_KEY}, 기본 local-dev-key)
  /ai/**         → 인증 없이 허용 (채팅 스트리밍)
  /sse, /mcp/**  → 인증 없이 허용 (Claude Desktop MCP 연결)
  /api/chat/**, /api/ollama/**, /api/documents/** → 인증 없이 허용

  세션 방식: STATELESS (JWT/세션 쿠키 없음)

9. 주요 API 엔드포인트
--------------------------------------------------------------------------------

  [채팅 스트리밍]
  GET /ai/rag/stream?message=...&model=...&sessionId=...   → SSE Flux<ChatResponse>
  GET /ai/simple/stream?message=...&model=...&sessionId=... → SSE Flux<ChatResponse>

  [세션 관리]
  POST   /api/chat/sessions           → 세션 생성
  GET    /api/chat/sessions           → 전체 세션 목록
  DELETE /api/chat/sessions/{id}      → 세션 삭제
  GET    /api/chat/sessions/{id}/messages → 세션 메시지 조회

  [문서]
  GET  /api/documents/status  → 문서 처리 상태
  POST /api/documents/reindex → 재인덱싱
  POST /api/documents/upload  → 문서 업로드

  [Ollama 모델]
  GET /api/ollama/models      → 설치된 모델 목록

  [웹 UI]
  GET /                       → chat.html (Thymeleaf)

  [MCP]
  GET /sse                    → MCP SSE 엔드포인트 (Claude Desktop 연결)
